# Milestone 43: Player-facing polish

Status: complete. It makes the depth the engine already has approachable from
inside the game, so it is Milestone 43 in the project sequence. After an eight
milestone run that deepened the ChromeSix systems, this milestone adds no new
mechanics: it surfaces what exists through a glanceable status line, in-game help
for the game commands, and a guided first few minutes for a new character. All
three slices have shipped.

## Goal

The combat, social, job, standing, and advancement systems are deep, but a player
sitting at a terminal cannot easily see their own vitals at a glance, cannot look
up the game commands from inside the game, and lands in the lobby with a bare
"Welcome" and no orientation. The reference for each of these already exists in
the engine or the docs; it is just not wired to where a player meets it.

This milestone closes that gap. It reuses renderers and content that are already
written, so it adds little source: a status verb over the existing meter, help
topics on the existing help object, and a first-contact flow over the existing
login and character-sheet gate.

## Background: what is already in place

- **The meter renderer.** `cs_meter` in `chromesix_verb.h` draws a ten-cell bar,
  `HP [#####-----] 18/21`. It is proven in the combat prompt (`verb_combat.c`
  draws HP, Grit, and Resolve bars there), but nothing outside combat uses it, so
  a player out of a fight has only the verbose `sheet`.
- **The condition readout.** `cs_condition` names the wound and BP band and
  `cs_cond_list` names the active conditions, both already used by `sheet`.
- **The help object.** `#0.help` (object `#800`) holds one topic per property, and
  `cmd_help` in `smolmoo.c` lists the topics or prints one, with a static fallback
  when the object is missing. It carries only the general commands (say, look,
  building, store, and so on); the ChromeSix verbs are documented in
  `chromesix-smolmoo.md`, a file a player cannot read from inside the game.
- **The login and sheet gate.** Login writes a bare "Welcome" and points at
  `help`. `verb_sheet.c` already special-cases a player with no `charid` sheet, so
  the un-created-character state is detectable; it is just not turned into
  guidance.

## Design: surface what exists

Each slice wires an existing renderer or body of content to where a player meets
it, rather than building new systems. The status line is a small verb over
`cs_meter`; the help is properties on the help object plus at most a small
`cmd_help` tweak; the onboarding is a message and a topic over the login path and
the existing no-sheet check. Nothing here changes a rule.

## Slice a: the status line (shipped)

- **`status`** (alias `st`), a non-setuid verb that reads the caller's own sheet.
  It prints the Section 12 one-liner over `cs_meter`: `HP [####------] 9/21  GRIT
  4/6  WOUNDS oo..` followed by the active conditions from `cs_cond_list` when any
  are set. It is the glanceable vitals line the verbose `sheet` does not give, and
  the same read a player wants after a fight without reopening the full sheet.

Shipped: `verb_status.c` (verbs 473 `status` and 474 `st`, non-setuid) draws the
HP and Grit bars with `cs_meter` (the same renderer the combat prompt uses), a
three-cell wound ladder from the `wounds` count, and, when any are set, the active
conditions from `cs_cond_list` in parentheses. It pays out a pending short rest
first, like `sheet`, and reports the no-sheet case with a pointer to `chargen`. A
smoke test sets known vitals in the unsafe lobby, so no rest payout shifts them,
and confirms the HP bar, the wound ladder, the conditions, and that the `st` alias
prints the same line.

## Slice b: in-game help for the game commands (shipped)

- **Game-command topics.** Seed the ChromeSix verbs onto the help object as topics
  so `help attack`, `help use`, `help jobs`, `help skills`, and the rest print a
  short reference in-game, mirroring how the general commands already work.
- **A `commands` index.** One topic that lists the game verbs by category (combat,
  gear, skills, jobs, social), so a player can find what exists without leaving
  the game.

Shipped: content only, no `cmd_help` change. Rather than one topic per verb, which
would swell the flat topic list, the game verbs are grouped into six area topics
on `#800` in the world seed (`character`, `combat`, `maneuvers`, `gear`, `jobs`,
`social`), each bundling its verbs with one-line usage in the style of the existing
`building` topic, plus a `commands` index that names the areas. `cmd_help` already
serves any property by name and lists them, so `help combat`, `help maneuvers`,
and `help commands` work with no code change. A smoke test confirms the `commands`
index lists the areas and that two area topics print their reference in-game.

## Slice c: new-player onboarding (shipped)

- **A first-contact flow.** A player whose character has not been set up is
  pointed at `chargen` in plain terms, the welcome line orients a fresh character
  to the starter loop, and a `start` help topic lays out the first few minutes.

Shipped: `chargen` now sets a `made` marker on completion. The character prototype
supplies default stats (so a bare sheet is not blank and `hook` is inherited),
which is why `made`, set only by finishing chargen, is the reliable "set up"
signal. A `login_welcome` helper in `smolmoo.c`, called from both the login and
account-creation paths, greets a made character with the returning-player line and
an unmade one with a pointer to `chargen` and `help start`. `verb_status` guides an
unmade character to `chargen` rather than printing a default readout as if it were
theirs. The `start` topic on `#800` lays out the first steps (chargen, look,
status, help commands, jobs, attack). A smoke test logs in a fresh account and
confirms the onboarding welcome, the status guidance, and the start topic.

## Deferred: the tutorial and the prompt

A scripted step-by-step tutorial (walking a new player through a first fight and a
first job) is a larger content effort and stays deferred; slice c gives the
orientation without the scripting. A persistent per-line prompt showing vitals
after every command is also deferred, since the `status` verb covers the same need
on demand without changing every output path.

## Verification

A smoke test drives each surface from a player session, the established pattern. It
damages a character and reads the status line, prints a game-command help topic
and the `commands` index, and confirms a fresh session is guided toward character
creation. These are deterministic reads, so no combat-timing polling is needed
beyond what the shared harness already provides.

## Dependencies

Depends on: M25a (the character sheet, the derived stats, and `cs_meter`,
`cs_condition`, and `cs_cond_list` the status line reads), the help object and
`cmd_help` (the general-command help system slice b extends), and M14 (accounts
and login, the path slice c orients).
