# Milestone 36: The unlock roster

Status: shipped. It gives the M35 `learn` verb something worth buying and builds
the table-driven unlock dispatch the ChromeSix design called for, so it is
Milestone 36 in the project sequence. Slice a (see the catalog), slice b
(table-driven active dispatch), and slice c (the starter roster) have all shipped.

## Goal

M35 shipped the growth loop, but its spend-on-unlocks half is hollow. `learn`
works, yet the `cs_unlocks` catalog holds only two entries: `smartlink`, which
chargen already grants, and the one `dermal` cyberware added so slice c was not
vacuous. A player also has no way to see what is learnable. And every active
unlock's effect is still a hardcoded branch in `verb_use.c`, so each new one is
new plumbing, not a table row.

This milestone fills the roster and finishes the machinery: a player can see the
catalog, an active unlock dispatches through the catalog instead of an `if`
chain, and a real spread of maneuvers, cyberware, and spells makes `learn` a
reason to keep earning CP.

## Background: what is already in place

- **The catalog.** `cs_unlocks` (in `chromesix_verb.h`) lists each id with its CP
  cost, required hook, and graft-slot use. `cs_unlock_find` and `cs_graft_count`
  read it; `learn` (`verb_learn.c`) prices and gates an acquisition against it.
- **The use side.** `verb_use.c` handles an active unlock by name in an `if`
  chain. Only `smartlink` is wired: it spends the turn and 2 Grit and sets `aim`,
  which `verb_attack.c` reads and clears on the next shot. A passive unlock has no
  entry here at all; `dermal` is read straight from `cs_recalc`.
- **The effect seams.** Passive effects are read where the stat is computed
  (`cs_recalc` for Soak, Passive Defense, Max BP, Max Grit). Active effects run as
  a turn action in `verb_use.c` and may set a flag another verb consumes (the
  `aim` pattern) or act at once.

## Slice a: See the catalog (shipped)

A player cannot learn what they cannot find. `learn` with no argument lists the
catalog rather than printing usage: each id with its CP cost, the hook it needs
(or none), and a status word, owned, affordable, or the reason it is locked (the
wrong hook, full graft slots, or too little CP). It reuses `cs_unlocks`,
`cs_has_unlock`, the sheet's `cp`, and the hook, so it is a read and a format, no
new state. This closes the discoverability gap M35c left and is the smallest
useful step.

Shipped: `list_catalog` in `verb_learn.c` prints each `cs_unlocks` row in aligned
columns (id, cost, hook or "any", status), with the status derived from prior
ownership, the hook match, the graft-slot cap, and the CP on hand. A smoke test
confirms an available unlock and, after learning it, that the same listing marks
it owned.

## Slice b: Table-driven active dispatch (shipped)

Fold the active-use side into the catalog so using an unlock is a lookup, not a
branch. Each `cs_unlocks` row gains what an active use needs: a Grit cost and an
effect tag (a small enum), with a tag that means "passive, not usable as an
action" for rows like `dermal`. `verb_use.c` becomes: resolve the word to a
catalog row, confirm the player has learned it, gate it to their turn, spend the
Grit, then switch on the effect tag to apply the effect. `smartlink` becomes the
first tagged row (its effect tag sets `aim`), so the refactor changes no player
behavior. This is the "single dispatch table keyed by id" `chromesix-smolmoo.md`
Section 2 specified, and it makes every later unlock a row plus, only for a
genuinely new kind of effect, one case.

Shipped: the `cs_unlocks` rows carry a `grit` cost and an `effect` tag
(`UEF_PASSIVE`, `UEF_AIM`), and `verb_use.c` dispatches through them: it finds the
word in the catalog, refuses a passive unlock ("works on its own"), checks the
unlock is learned, gates it to the turn, spends the Grit, and switches on the tag.
`smartlink` is the `UEF_AIM` row and still aims and fires unchanged, so the M25
and M35 combat tests pass. A smoke test also confirms `use dermal` is refused as
passive.

## Slice c: A starter roster (shipped)

With the dispatch in place, add a real spread across the hooks, each a catalog
row plus its effect at an existing seam. The shipped roster is deliberately small
and grows one row at a time:

- **`smartlink`** (maneuver, no hook): the active aim maneuver from M25, now the
  `UEF_AIM` row, so the no-hook maneuver kind is represented and the active path
  is exercised.
- **`dermal`** (cyberware, cyber hook, a graft slot): +2 Soak, from M35c.
- **`reflex`** (cyberware, cyber hook, a graft slot): +2 Passive Defense, read
  live by `cs_recalc`. With `dermal` it fills both graft slots.
- **`vigor`** (spell, awakened hook): +3 Max Grit, read by `cs_recalc`, which
  newly exercises the awakened gate `learn` enforces.

`reflex` and `vigor` are the two new entries, each a catalog row and one line in
`cs_recalc`, no new plumbing, which is what slice b bought. The exact effects and
numbers were chosen against the rulebook, the same way M35 left CP amounts to
tuning. An active roster entry beyond `smartlink` would add one `UEF_*` case in
`verb_use.c`; the passive entries need no verb code at all.

### Verification

Shipped: `cs_unlocks` carries the `reflex` and `vigor` rows, and `cs_recalc`
reads each for its bonus. A smoke test funds TestPlayer1, learns `reflex` under
the cyber hook and confirms Defense rises by two, then learns `vigor` under the
awakened hook and confirms Max Grit rises by three. The catalog listing and the
combat tests are unchanged.

## Verification

A smoke test lists the catalog and confirms an owned, an affordable, and a locked
entry each read correctly; learns a new active maneuver and uses it in a fight,
confirming the effect and the Grit spend through the table dispatch; learns a new
passive cyberware and confirms its derived-stat change; and, with the awakened
hook, learns and casts the spell. `smartlink` still aims and fires unchanged, so
the M25 and M35 combat tests pass as before.

## Dependencies

Depends on: M35c (the `cs_unlocks` catalog and `learn`), M25d (the maneuver and
Grit machinery and the `aim` seam), and M25a (the sheet and derived stats this
reads and writes).
