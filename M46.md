# Milestone 46: The living district (NPC respawn)

Status: planned. It makes the starter district repopulate on its own, so it is
Milestone 46 in the project sequence. M44 seeded a playable district but left it a
one-shot, and M45 finished the combat engine that fights those encounters. This
milestone closes the last gap that keeps the district from being a replayable loop:
its foes do not come back.

## Goal

The reset machinery exists but nothing drives it automatically. `@reset` reconciles
the seeded reset rules only when a wizard types it, and no rule ships in the world
seed, so the M44 encounter was hand-placed: kill the cargo-bay scavenger once and
the bay is empty for the rest of the session. A living district needs its foes to
repopulate without a wizard in the loop.

This milestone seeds the district's encounter as a reset rule, reconciles the world
at boot so it starts populated, and adds a timed auto-reset so a cleared encounter
comes back on its own. It is mostly wiring on machinery that already exists, plus a
test-hygiene fix, so it validates the district as a replayable game without growing
the codebase much. It also unblocks respawn for every future district, since the
pattern is seeded once here.

## Background: what is already in place

- **The reset rule.** A rule is a child of `#910` (`RESET_PARENT`) naming a `room`,
  a `proto` to clone, and a `count`. `@reset` tops each room up to that many live
  (non-downed) children of the proto, cloning the shortfall, and marks each clone
  `reset_spawn` so the corpse sweep may reclaim it once it is defeated. It is
  idempotent: a second pass spawns nothing until an instance dies.
- **The area filter.** `@reset #<area>` reconciles only the rules whose `area`
  property matches, so a district can be reset as a unit without touching the rest
  of the world.
- **No automatic driver.** There is no boot reset and no timed reset today; the
  reconcile runs only from the wizard command. The M44 plan noted this, which is
  why its foe was hand-placed rather than rule-managed.
- **The corpse sweep.** A defeated `reset_spawn` body is reaped after its lootable
  window, so downed instances do not pile up and the freed slot is available for the
  next reconcile.
- **The timer pattern.** `autosave_cb` is a host timer that re-arms itself with
  `timer_add` every `AUTOSAVE_MS`. A periodic auto-reset follows the same shape.

## The core tension and its fix

A seeded reset rule is processed by every global `@reset`, and the OLC tests call
global `@reset` and assert exact spawn counts. A permanent district rule would drift
those counts, which is the reason M44 deferred this. The fix is twofold: scope the
OLC count-asserting tests to their own area (`@reset #<test-area>`) so they only
reconcile their own rule, and gate the new auto-reset per area so the periodic timer
sweeps only areas that opt in. Test-created rules live in no auto-reset area, so
they are never touched, and the suite stays deterministic.

## Slice a: reconcile at boot and the seeded rule

Make the world start populated and the seeded encounter rule-managed.

- Factor the `@reset` reconcile loop into a reusable `world_reset(filter)` that both
  the command and the new drivers call, and run it once at boot after the world
  loads, so the district is populated with no wizard action.
- Re-add the district area (`#920`) and seed a reset rule (`#921`: room `#125`,
  proto `#221`, count 1, area `#920`). Turn the scavenger `#221` into a pure proto
  by dropping its hand-placed `location`, so the rule clones a fresh instance into
  the cargo bay rather than counting the template itself.
- Scope the OLC reset-count tests to their own area so the seeded rule cannot
  perturb them.

A smoke test confirms the cargo bay is populated at boot with no wizard command,
that downing the scavenger and running `@reset #920` respawns exactly it, and that
the OLC count tests still read their own spawns now that they are area-scoped.

## Slice b: periodic auto-reset (the living part)

Add the timer that makes the district live.

- A host timer, in the shape of `autosave_cb`, walks the areas carrying an
  `autoreset=<seconds>` interval and reconciles each area whose interval has
  elapsed, tracking a last-reset stamp per area so an area resets no faster than its
  interval.
- Seed `autoreset` on `#920`. Because the sweep visits only autoreset areas,
  test-created rules (which belong to no such area) are never reconciled by the
  timer, so the suite is undisturbed.

A smoke test downs the seeded scavenger, waits the interval (tunable short, like the
short-rest clock, so the test runs in seconds), and confirms it respawns with no
command typed.

## Slice c: respawn safety and the living loop

Make respawn a good citizen and prove the whole loop.

- Skip a room with an active fight (`cb_active`) when reconciling, so a foe never
  pops into an open scene, and confirm the corpse-sweep interplay: a reaped
  `reset_spawn` body frees the slot, and the next tick refills it.
- Extend the district with a second respawning encounter (or the guard), and drive
  the full loop: clear the district, let it repopulate over time, and confirm the
  M44 jobs and standing still resolve against the fresh instances (a bounty target
  that respawned is still the bounty target by name).

Deferred: respawn variety (wandering spawns, counts that scale with players, timed
waves) stays as later content, once the one-district pattern is proven.

## Verification

A smoke test drives the seeded district against the real reset machinery: boot
population, a manual area reset, timed auto-respawn, and the no-respawn-in-a-fight
guard, plus the OLC reset-count tests staying green now that they are area-scoped.
Driving the seeded rule rather than test-built rules is the point, since it exercises
the boot-and-timer path the isolated tests never touch. The combat parts poll for
the scene outcome before the next command, the established pattern.

## Dependencies

Depends on: M32-M33 (the OLC reset rules, areas, and the `@reset` machinery this
milestone drives), M44 (the seeded district and its hand-placed foe that becomes
rule-managed), M39 (the timed-recovery pattern the auto-reset timer mirrors), and
the M25c-M45 combat arc (the encounters that respawn and the conditions a fresh
instance starts clear of).
