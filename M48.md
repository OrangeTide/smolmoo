# Milestone 48: Hermetic world history (re-base a foreign chain)

Status: planned. It makes an instance's history depend only on its own key, so it is
Milestone 48 in the project sequence. M29-M31 built signed world history, and every
milestone since has grown the smoke suite that exercises it. This milestone closes a
fragility in that history: an instance that starts on a depot signed by another key
cannot extend or rewind the chain it inherits.

## Goal

Signed history is self-certifying: each version record embeds the signer's public key
and a `topic_id` derived from it, and a chain must stay one topic, since
`cas_vchain_walk` checks `prev.topic_id == v.topic_id` at every link. That is correct,
but nothing stops an instance from trying to build on a chain it did not sign. When a
depot carries a history head from a different key, the instance reads that head, then
its first save appends a record under its own key whose predecessor is the foreign
head. The chain now has a topic seam, and a later `@rewind` walking back across it
stops at `CAS_SIGN_ETOPIC` and dead-ends.

This bites in two places. The isolated test instances copy `depot/*`, which is
gitignored and can carry a head left by an earlier `make run`, so their `@rewind`
tests break for reasons unrelated to the code under test. And the same happens to any
restored backup: bring a depot up under a new key and its history is unrewindable.
The M45 notes flagged the test symptom and blamed it on the suite crossing
`AUTOSAVE_MS`. That was the wrong cause. The real trigger is a foreign-topic head in
the copied depot, and a pristine (headless) depot is why a clean rebuild always
passed.

This milestone makes history hermetic: an instance whose depot names a chain it did
not sign re-bases, starting a fresh self-signed chain at the current world root rather
than trying to extend a chain it cannot continue. The world data is untouched; only
the history chain re-bases. It is a small change on machinery that already exists, and
it fixes both the flaky tests and the restore-a-backup path with one rule.

## Background: what is already in place

- **Self-certifying records.** `cas_vrec_decode` (`smolvfs/cas-sign.c`) reads a
  record's embedded pubkey, derives the expected `topic_id`, and verifies the
  signature against that key. A foreign record decodes as valid, just in another
  topic.
- **One-topic chains.** `cas_vchain_walk` enforces topic continuity across links and
  returns `CAS_SIGN_ETOPIC` when a predecessor belongs to a different topic, and
  `CAS_SIGN_ECHAIN` when the seq does not link. `@rewind` walks the chain through it.
- **Head load without a topic check.** `history_load_head` (`smolmoo.c:1504`) reads
  `depot/head`, decodes the record it names, and sets `head_addr` and `head_seq`. It
  does not compare the record's topic to the local key, so a foreign head is accepted.
- **Key load or generate at start.** `history_init` (`smolmoo.c:1536`) loads the
  signing key, generating one on first run, then calls `history_load_head` and turns
  signing on. `cas_sign_topic_id` derives a topic id from a pubkey, so the local
  topic is available right after the key loads.
- **The isolated test pattern.** The `@rewind`, agent-persistence, and `@gc` tests
  each start a private server on a temp depot copied from `depot/*`, with its own key
  at `<depot>.key`. They are the instances that inherit a foreign head.

## Design: re-base a chain the instance did not sign

After the key is ready in `history_init`, derive the local topic from `server_pk` and
check it against the head the depot names. If the head record belongs to a foreign
topic (or cannot be decoded, or its chain does not link), the instance does not adopt
it: it clears the head to genesis (empty `head_addr`, seq 0) and logs a re-base. The
next save then writes seq 1 under the local key with an empty `prev`, starting a fresh
self-signed chain rooted at the current world state. Nothing in the world data
changes, and the foreign records stay in the store as unreferenced objects.

The rule is the same one a chain already enforces internally, applied one step
earlier: an instance builds only on history in its own topic. Applying it at load,
rather than letting the seam surface at the first `@rewind`, is what makes the
behavior predictable and the tests hermetic.

## Slice a: re-base a foreign-topic head at load (shipped)

The core rule.

- In `history_init`, after the key is loaded or generated, compare the local topic
  (`cas_sign_topic_id(server_pk)`) to the topic of the record `depot/head` names. On a
  mismatch, treat it as genesis: leave `head_addr` empty and `head_seq` at 0, and log
  that history re-based off a foreign key.
- Leave the world root and object map untouched, so only the history chain resets.

A smoke test plants a foreign head in an isolated depot: a throwaway server signs a
depot with one key, then a second server starts on a copy under a different key. The
second instance logs the re-base, and its `@save`/`@rewind` build and rewind a clean
chain, where before the rewind dead-ended at the topic seam.

Shipped: `history_load_head` in `smolmoo.c` now decodes the head record and compares
its `topic_id` to the local topic (`cas_sign_topic_id(server_pk)`). On a mismatch it
leaves the head at genesis (empty `head_addr`, seq 0) and logs that the head belongs
to a foreign key and is re-basing; a head that cannot be decoded at all folds into the
same fresh-chain path. The world root and object map are untouched, so only the
history chain resets and the next save starts seq 1 under the local key with an empty
`prev`. A smoke test signs a depot under one key with a throwaway server, brings a
second instance up on a copy under a fresh key, and confirms it logs the re-base and
that its `@save`/`@rewind` build and rewind a clean self-signed chain. Reverting the
change was confirmed to break both checks (no re-base, and `@rewind` dead-ends at the
topic seam), so the test exercises the fix. The suite grew to 448 checks.

## Slice b: robustness and the restore path (shipped)

Cover the neighboring failures and prove the operational case.

- Fold a head that will not open (a partial or damaged depot) or will not decode into
  the same re-base path, and log every re-base with the reason, so a damaged head
  starts a fresh chain instead of a silent or cryptic result.
- Confirm `@history` and `@rewind` report a clear result on a re-based instance (a
  fresh chain, not an error), so an operator sees history start over rather than a
  cryptic failure.

A smoke test proves the damaged-depot case: build a chain, point its head at an object
that is not present, and start an instance on that depot under its own key. It logs
the re-base, and `@history` lists a clean chain while `@rewind` returns to its
re-based genesis.

Shipped: `history_load_head` now reports one reason per re-base ("head record is
missing", "head record is unreadable", or "head belongs to a foreign key"), so the
open-fail case that was previously silent is logged like the others. A smoke test
damages a head by pointing it at an absent object, keeping the depot's key so this is
the damaged-depot path rather than M48a's foreign-key path, and confirms the instance
re-bases, `@history` lists the fresh chain, and `@rewind` returns to its genesis. The
suite grew to 451 checks.

A validation walk of the adopted chain at load was considered and dropped: `@rewind`
already returns a clear message on a broken chain rather than crashing, the history
chains this harness builds keep a single record so a missing-predecessor case cannot
be constructed to test it, and shipping untested defensive code is the wrong trade.
Proactively re-basing a chain-broken head stays available for a later milestone if a
real partial-copy case justifies it.

## Slice c: retire the debt

With re-base cutting the dependency on the copied depot's signing state, the isolated
tests are hermetic regardless of suite runtime or a stale `depot/`.

- Remove the `AUTOSAVE_MS`-margin caveat from `PLAN.md` (the M45 record) and the note
  in `M45.md`, since the cause is now understood and fixed.
- Document in `README.md` that restoring a depot under a new key starts a fresh,
  self-signed history while preserving the world, so the behavior is a stated feature
  rather than a surprise.
- Confirm the `@rewind`, agent-persistence, and `@gc` isolated tests pass with a
  foreign head deliberately present, proving the coupling is gone.

## Deferred: multi-key trust and chain migration

Verifying a chain against a set of trusted keys (so an instance could accept history
from a known peer), and migrating a chain to a new key while preserving its seq
history (re-signing prior roots), stay deferred. Both belong with the federation stack
in `FUTURE.md`, which is gated on server maturity. This milestone's rule, build only
on your own topic, is what a single server needs, and it does not foreclose either
later direction.

## Verification

A smoke test drives the re-base against a deliberately foreign head: it confirms an
instance whose depot names a chain signed by another key starts a fresh self-signed
chain, that `@save` extends it and `@rewind` returns to its genesis, and that a
damaged or partial head folds into the same path. The isolated history tests are run
with a foreign head present, proving they no longer depend on a pristine `depot/` or
on total suite runtime.

## Dependencies

Depends on: M29-M31 (signed world history, `@history`, `@rewind`, and the
`cas-sign` chain this milestone re-bases), and the isolated-instance test pattern
those milestones established, which is the harness the re-base is proven against.
