# Milestone 35: Character advancement

Status: in progress. It closes the ChromeSix growth loop that M25 designed but
left inert, so it is Milestone 35 in the project sequence. Slice a (earn CP) and
slice b (spend CP to raise a skill) have shipped; slice c (5 CP unlocks) is gated
on the unlock catalog.

## Goal

A character freezes at creation. `chargen` sets attributes and skills once, and
nothing since changes the sheet: a player fights, talks, buys, and travels, but
does not grow. The currency for growth already exists. `chromesix-smolmoo.md`
documents `cp` (Character Points, the growth XP), M25a seeds every character with
10 CP, and `cs_has_unlock` already reads the `maneuvers` list of 5 CP unlocks.
What is missing is the loop that earns and spends it.

This milestone wires that loop: play awards CP, and CP buys a better sheet. It
adds no new subsystem. It hooks the scene resolver combat already runs and reuses
the skill table, caps, and the points model chargen already uses.

## Background: what is already in place

- **The currency.** The sheet carries `cp`. It is set at creation and read by the
  `sheet` verb, but never awarded or spent in play.
- **The scene resolver.** The `__combat` agent (`verb_combat.c`) drives both a
  fight and a social scene on one engine. It ends a scene the player wins at a
  single point: `foes_up(ids, n, player) == 0`, which broadcasts "The fight is
  over." or, for a social scene, "The matter is settled." The player conceding,
  fleeing, or being downed takes other branches and is not a win.
- **The skill model.** `cs_skills` (in `chromesix_verb.h`) is the skill table,
  each skill keyed to an attribute. A skill is stored as points, where
  `dice = points / 3` and `pips = points % 3`. `chargen` already validates a
  raise against the attribute cap.
- **The unlock model.** Every maneuver, cyberware mod, and spell is one id in the
  `maneuvers` list, each costing 5 CP, checked with `cs_has_unlock`. `chargen`
  grants the first one (`smartlink`); nothing acquires one afterward.

## Slice a: Earn CP (shipped)

Award Character Points where a scene resolves in the player's favor. The single
win point in `__combat`, `foes_up(...) == 0`, is the only hook, so one change
covers both a fight and a social scene.

- **The award.** When the player's side wins, add CP to the player's sheet and
  announce it ("You gain N Character Points."). A concede, a flee, or a downed
  player wins nothing.
- **The amount.** Sum a per-foe value over the roster rather than a flat scene
  award, so a harder scene is worth more. Each NPC sheet may carry a `cp_award`
  property; a foe with none contributes a small default. A social win may be
  worth less than a fight, or the same; the plan leaves the exact numbers to
  tuning in the slice, since they are one table, not new plumbing.
- **No farming.** The award fires once per scene at the resolver, not per foe
  downed, so it cannot be re-triggered by re-opening a settled scene. This is the
  same settle-before-continue discipline the combat and social tests already
  follow.

Shipped: `award_cp` in `verb_combat.c` sums each roster foe's `cp_award` (a base
of 1 when it names none), adds the total to the player sheet's `cp` under the
task's grant, and announces it with `puts` to the winner. It is called once at
the win point, after the "fight is over" / "matter is settled" broadcast. A smoke
test wins the raider fight and confirms the "You gain 1 Character Point" award
for the single default foe.

## Slice b: Spend CP to raise a skill (shipped)

A `train <skill>` verb spends CP to raise one skill by one pip (one point in the
stored model).

- **The cost.** Raising a skill costs CP equal to the dice the character has in
  it now (`points / 3`, minimum one), the OpenD6 advancement rule. Raising a
  well-developed skill costs more than a raw one. The exact rule is confirmed
  against the rulebook in the slice; if the rulebook gives a different cost, that
  one wins.
- **The checks.** Refuse when the character lacks the CP, exactly like any costly
  command today, and refuse a raise past the skill's cap. The chargen cap is
  attribute-relative; the advancement cap may be higher, so the slice settles the
  cap it enforces and states it.
- **The effect.** Deduct the CP, raise the skill by one point, confirm the new
  rating. It reuses `cs_skills` for the name lookup and the points model for the
  rating, so it is a lookup, a cost check, and a write.

Shipped: `verb_train.c` (verb 459, `train <skill>`, non-setuid like chargen since
it writes only the caller's own sheet). The cost is the skill's current rating in
dice (`(attribute + skill points) / 3`, at least one), the cap is the same
attribute + 6 skill points chargen enforces, and it refuses an unknown skill, a
raise past the cap, and a raise the character cannot afford. A smoke test gives
TestPlayer1 a known CP budget, trains firearms (confirming the raise and the
spend), then confirms an unknown skill and a zero-CP raise are both refused.

## Slice c: Spend CP on a 5 CP unlock (gated)

A verb to spend 5 CP to add a maneuver, cyberware mod, or spell id to the
`maneuvers` list, the acquire path the unlock model was built for.

- **What it needs.** The unified unlock table `chromesix-smolmoo.md` describes,
  keyed by id with each option's cost, its requirements (a graft-slot cap for
  cyberware, the Awakened hook for spells), and its effect. Today only the check
  and use side exists (`cs_has_unlock`, and `smartlink` granted at chargen); the
  catalog of acquirable ids is not built out.
- **Why it is gated.** Without that catalog this slice has nothing to sell. It is
  therefore deferred within the milestone: M35 ships as slices a and b, and slice
  c lands when the unlock catalog is real. This keeps the earn-and-spend loop
  shipping now without waiting on the larger unlock table.

## Verification

A smoke test drives the full loop as a non-admin player (test accounts are admin,
which masks nothing here but keeps the pattern honest): create a character, note
its CP, win a fight against a mob, and confirm the CP rises by the expected
amount and the win announces it. Then `train` a skill, confirming the CP drops by
the cost and the skill rating rises, and that a `train` with too little CP is
refused and a raise past the cap is refused. The award fires once, so the test
polls for the scene to settle before probing, the same discipline the existing
combat and social tests use.

## Dependencies

Depends on: M25c-e (the combat and social scenes and their resolver), M25a (the
sheet and `cp`), and chargen (the skill table, caps, and points model this reads
and writes).
