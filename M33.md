# Milestone 33: Builder self-sufficiency (OLC-8)

Status: in progress. It continues the OLC arc (see `OLC.md`, Milestone 32 in
`PLAN.md`), so it is numbered OLC-8 in that arc and Milestone 33 in the project
sequence. M33a (in-game agent authoring), M33b (ownership quotas), and M33c
(prototype discovery) have shipped; M33d is still planned (and optional).

## Goal

OLC-1 through OLC-7 made the world buildable and simulable from inside the
running game: a builder creates rooms, items, mobs, stores, and vehicles,
stocks them with reset rules, and wakes agents that keep the world alive with
no player present. Two gaps still tie a builder to the maintainer and the repo
tree:

1. Agents (the programs behind wandering mobs and running vehicles) must be
   written as C in the repo and compiled at build time. `@program` compiles a
   one-shot verb in-game, but not an event-loop agent, so a builder cannot
   author a new brain without a rebuild.
2. Open building has no guardrails. There is no per-account object cap, so a
   runaway `@create`/`@clone` loop can exhaust the id space, and no in-game way
   to discover the base prototypes a builder must name as parents.

Closing these completes the OLC promise: a builder runs a living, self-authored
world without touching the repo. The work is small and stays inside the
size constraint. Each piece is already named as a follow-up in `OLC.md`.

## Design decision: same split as OLC

The OLC rule holds. Simulation logic ships as verbs on the RV32 VM; the
permission-sensitive builder and admin tools stay host C in `smolmoo.c`, where
the permission helpers (`is_wizard`, `obj_owner_match`) and the object table are
in reach. OLC-8a is a change to the in-game compile path, which is host C
already. OLC-8b and OLC-8c are host checks and a host listing, for the same
reason OLC-1's toolkit is host: they must act with the caller's authority and
touch object internals.

## M33a: In-game agent authoring (`@program ... agent`) (shipped)

Today an agent is a `.c` file whose name carries the `agent_` prefix. The
installer keys on that prefix to link `verbmain.o`, the generic event-loop
`main()` that an agent runs instead of defining its own. An agent supplies
`on_event()` and `verb_dwell()`; the CRT's `_start` calls `verbmain`'s `main()`,
which loops on `sys_getmsg`/`on_event` and synthesizes an `EV_TIMER` on a dwell
timeout. This build path already exists (see the Makefile `verbmain.o` rule and
`sdk/runtime/verbmain.c`).

In-game source has no filename, so `@program` cannot see an `agent_` prefix. It
sniffs C from an `#include` and MooScript otherwise, or takes an explicit
`@program #N c` / `@program #N moo`. This slice adds a third form:

    @program #N agent      compile #N.src as an event-loop agent (C)

`agent` implies C (agents link the C runtime), so it selects the C compiler and
links `-lverbmain` in place of the one-shot CRT-to-`main` path. Everything else
in the pipeline is unchanged: the source is compiled to an RV32 ELF, hashed,
stored in the CAS, and set on `#N.elf`. The result is exactly what an
`agent_*.c` verb produces today, so `@wake #N` runs it under the system session
with no further change, and the boot-scan persistence (OLC-5) re-wakes it after
a restart or `@rewind`.

A builder then writes a brain in the web editor:

    @create #400
    @set #N.verb=__mybrain
    @edit #N.src              write on_event() and verb_dwell() in C
    @program #N agent
    @set #M.brain=#N          point a mob or vehicle at it
    @wake #M

Scope: C agents only. MooScript agents would need the MooScript runtime to
supply an event-loop entry, which it does not have, so they stay out of scope
here (the one-shot MooScript verb path is unchanged). The `agent` token is the
one deferral OLC-5 named; this slice is that follow-up.

Shipped: `program_compile` takes an `is_agent` flag and appends `verbmain.o` to
the C link, and the `@program` handler recognizes the `agent` token. A smoke
test authors a widget agent in-game (source that broadcasts on each `EV_TIMER`),
`@program #N agent`, points an object's `brain` at it, `@wake`s it, and confirms
the broadcast lands. help.md's `programming` topic documents the token.

## M33b: Ownership quotas (shipped)

As `@create` and `@clone` open up to non-wizard builders, an unbounded or
buggy loop can march the persistent id space toward `OBJ_EPH_BASE`. A small
host-side cap prevents that.

- A per-account live-object count, checked in the three creation paths:
  `sys_create` (syscall 16), the `@create` host command, and `@clone`. Over the
  cap, creation is refused with a clear message rather than partially
  succeeding.
- Wizards are exempt, the same bypass the permission checks already grant, so
  world seeding and admin tools are unaffected.
- The cap is a tuning knob, a single constant (or a `#0` property so an operator
  can set it without a rebuild). Default generous enough that ordinary building
  never hits it.
- Counting: a scan of the object table (`acct_over_quota`), short-circuited the
  moment the count reaches the cap, so it does no more work than the cap when a
  builder is over it. The table is bounded (`MAX_OBJ`), so a running tally was
  not needed; add one only if the scan ever shows up in practice.

Shipped: `obj_quota` reads `#0.objquota` (default 256), and `acct_over_quota`
gates all three creation paths, `sys_create` (returning `-E_QUOTA`), `@create`,
and `@clone` (a clear message). Wizards are exempt through `acct_is_wizard`. A
smoke test drives it as the non-admin `TestPlayer3`: over a lowered quota the
next create is refused and makes no object, a wizard still creates freely, and
raising the quota lets the builder create again.

## M33c: Prototype discovery (`@proto list`) (shipped)

`@create #<parent>` needs the builder to know parent ids. The base prototypes
are registered on the system object (`#0.room`, `#0.exit`, `#0.creature`,
`#0.combat`, `#0.verb` `#400`, `#0.reset` `#910`, `#0.area` `#900`, and so on),
but nothing lists them in-game. A small read-only command closes that:

    @proto list        list the base prototypes registered on #0

It walks the `#0` properties whose value is an object reference to a prototype
and prints each id, its registered name, and its `name` property, so a builder
can pick a parent without reading source. Read-only and unprivileged; it
exposes only what `@examine #0` already would.

It shipped as a host command, not a verb. A verb can read `#0` by name but
cannot enumerate `#0`'s property keys (there is no `sys_nextprop`), so it could
not list registrations it does not already know. The host walks `#0`'s props
directly and prints each objref-valued one as `<key> #<id> <name>`.

Shipped: the `@proto` handler in `smolmoo.c`, read-only and unprivileged. A
smoke test runs `@proto list` as the non-admin `TestPlayer3` and confirms the
seeded prototypes (Room Prototype, Reset Prototype) appear. Documented in
help.md's `building` topic.

## M33d: Generic `@clone` list-values (deferred)

`@clone` copies all scalar and objref properties but skips list-valued ones,
which no world object uses today (noted in OLC-1). Supporting them is only
worth doing if a world starts storing list-valued props. Deferred unless a
concrete need appears; the type-aware clone that exists covers the common
cases.

## Dependencies and non-goals

Depends on: OLC-5 (the agent runtime, `@wake`/`@sleep`, boot-scan) for M33a;
OLC-1 (`@create`/`@clone`/`@recycle`) for M33b and M33c.

Non-goals: this milestone does not start the federation stack (SHOAL, peering,
backup follower), which is deferred to a distant future in `FUTURE.md`, gated by
server maturity (hundreds of active players) rather than explored ahead of that.
It also does not add gameplay (a `sell` verb, NPC disposition, idle chatter);
those are a separate track if player-facing depth is the priority instead.

## Verification summary

Each slice gets an HTTP smoke test in `test.sh` in the established style, and
the permission-sensitive slices (M33b, and M33c if it stays host) are checked as
the non-admin `TestPlayer3` so admin status does not mask a regression. Run
`make install` before `make test` after changing verbs or the world, and follow
the turn-loop poll pattern only where a slice touches a scene (none here do).
