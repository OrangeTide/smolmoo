# Milestone 52: Quest board and objective tracking

Status: shipped (slices a, b, c; 803ab4d, 90f98e5, 401f38b). It makes the campaign content a district holds discoverable and an active
goal legible in the world, so it is Milestone 52 in the project sequence. M37 built jobs,
M47 chained them behind earned flags, and M51 surfaced a player's own contract, clearances,
and standing. What is still invisible is the wider offering: a player only sees the
contracts in the room they stand in, and an accepted goal names a target or a destination
without saying where it is. This milestone surfaces both.

## Goal

A player who walks into a district cannot see what work it holds without visiting every
room, since `jobs` lists only the givers in the current room. An accepted contract names its
objective (a bounty target creature, or a courier destination room) but not where that
objective is, so a new player does not know which way to go. Both gaps make the seeded
campaign content harder to find than to play.

This milestone adds a district-wide view and a live sense of direction. A `board` command
lists every open contract reachable from where the player stands, each with its giver, its
room, its reward, and whether it is locked behind standing or a flag. The active-contract
briefing gains an objective status: a courier goal shows the next step toward its
destination, and a bounty goal shows whether its target is still standing. Both read state
that already exists (giver props, room exits, the sheet), so the milestone is content-light
in code and adds no new mechanics. It walks the room graph the world already forms through
exits, rather than introducing a district data structure.

## Background: what is already in place

- **The job giver.** A giver is a builder object with `job`=1 carrying a contract in props:
  `job_desc`, a goal (`job_target` creature name for a bounty, or `job_dest` room id for a
  courier), rewards (`job_cp`, `job_creds`, `job_standing`), and the gates (`job_min`
  standing, `job_need` flag). `show_offer` in `verb_jobs.c` already renders one giver's
  offer and marks it locked when the `job_min` or `job_need` gate is unmet.
- **The room graph.** Rooms are linked by exit objects contained in a room (found through
  `sys_next(room, e)`), each carrying a `dest` prop with the destination room id as a string
  and a `name` (the direction). `verb_go.c` reads `dest` to move. There is no district
  object; a district is just a connected set of rooms, so a district-wide view is a bounded
  walk of the exit graph from the player's room.
- **The contract views.** `jobs` lists the current room's offers and the active-contract
  briefing; `contracts` (M51c) consolidates the briefing, clearances, and standing. The
  briefing is `show_briefing` in `verb_jobs.c`, which reads the giver the sheet points to.
- **The completion hooks.** A bounty sets `job_done` when the target is defeated (M37b); a
  courier sets it on arriving at `job_dest` (M37c). So the briefing already distinguishes
  "in progress" from "done; report back", but says nothing about where the goal is.

## Design: walk the exit graph the world already forms

The rework centres on one shared traversal of the room graph, used two ways. A bounded
breadth-first walk from the player's current room follows each room's exits by their `dest`,
visiting each room once up to a fixed cap, so a fully connected world yields a local
neighbourhood rather than the whole map. The cap is a small fixed array of visited room ids,
sized for a district, not the world.

- **The board.** Walk the neighbourhood, and in each visited room list every `job`=1 giver
  through the existing `show_offer`, prefixed with the room it sits in. This reuses the offer
  rendering (name, description, reward, and the locked marker for an unmet standing or flag
  gate) so the board and the in-room `jobs` list agree on how a contract reads.
- **The breadcrumb.** For an active courier contract, run the same walk toward the goal:
  breadth-first from the current room until the `job_dest` room is reached, and report the
  first exit on that path by its direction name, so the briefing can say which way to go.
  When the destination is the current room, or unreachable within the cap, say so plainly.
- **The bounty status.** A bounty target is a creature that can be anywhere, so there is no
  path to trace; the objective line instead reports whether the target still stands (the
  `job_done` flag the win hook sets), turning the bare "in progress" into "target still at
  large" or "target down, report back".

Every new view reads the caller's own sheet and world state without writing, so the verbs
stay non-setuid, the way `jobs`, `sheet`, and `contracts` do. The traversal is bounded and
allocates a fixed array, so it cannot run away on a large or cyclic graph.

## Slice a: the district quest board

List the contracts a district holds, not just the current room's.

- Add a bounded breadth-first walk of the room graph from the player's current room
  (following each room's exit `dest` props, each room visited once up to a fixed cap).
- Add a `board` verb (routed through `verb_jobs.c`) that walks the neighbourhood and lists
  every `job`=1 giver found through `show_offer`, prefixed with its room, marking a
  standing- or flag-gated contract locked. Register it like `jobs`, non-setuid.

A smoke test seeds two rooms one exit apart, each with a giver (one open, one gated), and
confirms `board` from either room lists both contracts with their rooms and the gated one
marked locked, where the in-room `jobs` would show only the local one.

## Slice b: objective tracking on the active contract

Give an accepted goal a sense of direction.

- Extend `show_briefing` so a courier contract shows the next step toward its `job_dest`:
  the direction of the first exit on the breadth-first path from the current room, or a
  clear line when the player is already there or it is out of reach.
- Show a bounty contract's target status from `job_done`: still at large, or down and ready
  to report.

A smoke test accepts a courier contract, then confirms the briefing (in `jobs` or
`contracts`) names the direction to head from the origin, and updates to "you are here" once
the player reaches the destination. A bounty test confirms the target reads as at large
before the fight and as down after.

## Slice c: flag labels (optional polish)

Make the earned clearances read as titles, not tokens.

- Add a small registry mapping a flag token to a prose label (a prop lookup on the system
  object, or a builder-set label per token), and render the label where a flag appears: the
  Clearances line and the `job_need` locked marker.
- Leave the raw token as the fallback when a flag has no label, so nothing regresses.

A smoke test gives a labelled flag and an unlabelled one, and confirms the labelled one
renders its prose in Clearances while the unlabelled one still shows its token.

## Deferred: cross-district travel routing and a persistent journal

Routing a breadcrumb across more than the local neighbourhood cap, a persistent quest
journal that records finished contracts, and a map view of the district stay deferred as
later content. The board and the breadcrumb answer "what is near me" and "which way now",
which is what a player in a scene needs; a world-scale router and a history of past work are
separate features, not this milestone's scope.

## Verification

A smoke test confirms the board lists a district's contracts with their rooms and lock
state from any room in it, the active courier briefing names the direction to its
destination and updates on arrival, a bounty briefing reflects whether its target still
stands, and (if slice c ships) a labelled flag renders its prose. The traversal is bounded,
so a healthy run's time is unchanged. The suite grows by the new checks; the milestone
surfaces existing state rather than adding mechanics. Driven on non-admin TestPlayer3, since
these are player-facing reads that admin authority does not change.

## Dependencies

Depends on: M37 (jobs, the giver contract fields, and `show_offer`), M38 (the standing gate
the board's locked marker reads), M44 (the seeded district of connected rooms the board
walks), M47 (the campaign-flag gate and the flags a label would name), and M51 (the
active-contract briefing this extends and the `contracts` view). It builds on the room and
exit model (`dest` props) that `verb_go.c` already traverses.
