# Milestone 55: New-player integrity

Status: shipped (slices a, b; a469b02, 09deeef). It closes two defects the M33-M52 review found
around a character that is playable before chargen has run, so it is Milestone 55 in the project
sequence. A fresh
character inherits playable stats from its prototype, so it can fight, train, and learn before
chargen is ever run. But the sheet shows that default state as though it were the player's own
character, and running chargen afterward overwrites the progress earned first. This milestone
keeps early play honest and lossless.

## Goal

A new character inherits attributes and a hook from its prototype, so `attack`, `train`, and
`learn` all work before chargen. Two things go wrong from there. First, `sheet` has no
made-marker guard, unlike `status` (M43c): an un-chargen'd player who types `sheet`, a very
likely first command, sees a full readout of the inherited defaults as if it were their own
character, which undercuts the onboarding that points them at chargen. Second, chargen's
finalize overwrites the character's skills, credits, stims, maneuvers, and CP with its starting
kit, so a player who fought, trained, or learned before running chargen (which the onboarding
text pushes them toward) loses all of it with no warning.

This milestone makes the pre-chargen state legible and the transition lossless. The sheet
guides an un-chargen'd player the way `status` does, rather than showing a default readout. And
chargen folds its starting kit into what the character already has, rather than stomping it, and
refuses to run a second time once the character is set up.

## Background: what is already in place

- **The made marker.** chargen's finalize sets `made=1`. `verb_status.c` (M43c) refuses its
  one-line readout when `made` is unset, printing "You haven't set up your character yet. Type
  'chargen' to begin." instead. `verb_sheet.c` has no such guard and renders the sheet for any
  character id at or above zero.
- **The playable prototype.** A new character sheet inherits playable defaults (attributes, a
  hook) from its prototype, so the pre-chargen `check firearms` already rolls a real pool (2D
  from the inherited Agility) and `attack`, `train`, and `learn` all function. Nothing gates
  them on `made`, and by decision this "playable from the prototype" behavior stays.
- **chargen's finalize.** After validating the three steps (attributes, hook, skills), it
  commits the step-3 skill points (`sk_<skill>` set to the allocation), then sets `money` to
  300, `stims` to 3, `maneuvers` to "smartlink", and `cp` to 10, recomputes BP and Grit to
  their maxima, sets `made=1`, and resets `cg_step` to 0. Because `cg_step` is cleared, a
  character that is already made can re-enter chargen from step 1 and be stomped again.
- **Earned progress.** `train` spends CP to raise a skill, `learn` spends CP to add a maneuver,
  and `award_cp` (combat) grants CP. All of these can run before chargen, so a pre-chargen
  character can carry raised skills, learned unlocks, and CP that the finalize would overwrite.

## Design: guide before setup, and fold setup into earned progress

Two independent fixes. The sheet gains the same made-guard `status` already has, so an unmade
character is guided rather than shown a default readout it might mistake for its own. chargen's
finalize stops overwriting: it merges its starting kit into the character's current pools, so
nothing earned is lost, and it refuses to re-run once the character is made, so the kit cannot
be granted twice. A character that runs chargen without having played first has earned nothing
beyond the prototype baseline, so the merge leaves it with the same standard starting kit as
before; the change is visible only for a character that earned progress first.

## Slice a: the sheet made-guard

Stop the sheet from presenting a default readout as the player's own.

- Add the `made` check to `verb_sheet.c`, matching `verb_status.c`: when `made` is unset, print
  the same guidance and return, rather than rendering the inherited defaults.
- Adapt the M25a pre-chargen check, which today reads a default sheet, to expect the guidance
  instead. Prototype inheritance stays covered by the pre-chargen `check firearms` (pool 2D),
  which reads no sheet, so nothing about inheritance goes untested.

A smoke test confirms a fresh character's `sheet` before chargen prints the guidance, and that
after chargen it renders the full readout as before.

## Slice b: chargen preserves progress

Make finalize lossless, and one-shot.

- Refuse chargen once the character is made: a character is set up once, so a re-entry after
  `made` is set prints a short "already set up" line and returns, which also stops the starting
  kit from being granted twice.
- In finalize, merge rather than overwrite: the starting credits, stims, and CP add to what the
  character has earned; each step-3 skill point adds to any level already trained into that
  skill; and "smartlink" is merged into the existing maneuvers list, keeping learned unlocks.
  BP and Grit still settle to their recomputed maxima. A fresh character, whose earned pools are
  the prototype baseline, still ends chargen with the standard kit.

A smoke test gives a not-yet-made character some earned progress (a trained skill, a learned
unlock, and CP from a win), runs chargen, and confirms the earned skill level, the unlock, and
the CP survive alongside the starting kit, then confirms a second chargen is refused.

## Deferred

Gating play behind chargen (the rejected alternative), a guided pre-chargen tutorial, and a
respec that re-runs chargen deliberately stay deferred. The prototype-playable model is kept by
decision; this milestone only makes it legible and lossless, not a different onboarding flow.

## Verification

A smoke test confirms an un-chargen'd character's `sheet` guides rather than shows a default
readout, that a character keeps the skills, unlocks, and CP it earned before running chargen,
and that chargen refuses to run twice. It is exercised where a fresh character is created and
played. The suite grows by the new checks and the adapted pre-chargen sheet check; the milestone
changes onboarding integrity, not the chargen rules or the sheet's layout.

## Dependencies

Depends on: M25a (the sheet, `cs_recalc`, and the chargen flow this extends), M35 (`train` and
`learn`, the earned progress the finalize now preserves), and M43c (the `made` marker and the
`status` guard this mirrors onto the sheet).
